Alias storage and cleanup
Component18 points to ordered16-byte rows {uint32 handle, uint64 alias at+8};
20/24 hold count/capacity,68 current alias,70 uint32 counter,74 mode. BD6A80
increments the counter with wrapping and retains the sampled handle before
allocation/notification. With storage, it appends that handle and alias. An
allocation failure still consumes/returns the sampled handle and may notify.
Notify occurs when the requested alias differs from component68. BD6C50 routes
to an engine queue; it does not directly select the last row or set current68.

BD6900 searches from the end for the caller's handle, removes the last matching
row and compacts in order. A successful removal leaves the caller's handle
unchanged. A miss clears it. Removing the last row notifies only when the new
last alias (or zero for an empty list) differs from current68. A successful
cleanup therefore need not clear State1C0 or issue a notification.
