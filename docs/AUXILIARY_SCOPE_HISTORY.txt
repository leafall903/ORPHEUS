Auxiliary scope history — explicit normal-forward host
Target: original Overwatch 1.74.0.0.104319; addresses are module RVAs.

Problem and resulting behavior
Manual Registry callbacks established the BD02E168/582E0D5F interfaces, but the
real helper's ordinary State transitions did not dispatch them. ForwardHost is
now an explicit service for one script Component. State transitions record the
native history protocol; an owner-driven drain dispatches its pending parity.
It is not automatically attached to Match, SceneWorld entities or body prediction.

Implemented service
  host = scopes.ForwardHost(component)
  world.set_subgraph_scopes(component.entity, host)
  host.set_frame(explicit_native_frame)
  ... owner runs the VM phase ...
  host.drain()

The host is bound to the exact Component object and its SceneWorld/entity.
An entity ID or UUID alone cannot supply that ownership. A missing frame is a
strict script failure before the first record. Frames must be signedint32 and
monotonic for this forward-only service; rewind is rejected. The owner chooses
when to advance it and drain. Component.run_frame/run_now do not invent a drain
boundary or native frame mapping. Unknown services and knownNone retain their
previous strict/passive meanings; plain Registry remains manually dispatched.

State.on_beginning records after counter increment and before exclusive aborts.
State.on_ending records while active/ending, before child cleanup. Active reentry
and inactive/repeated end do not enqueue extra records. Registration stays cold.
Only the verified BD02E168/582E0D5F null+18 interfaces are accepted by ForwardHost.
All scans/callbacks share the VM work budget; callback cycles fail the Component.

Live explicit unregister processes pending history and uses native swap removal.
VM destruction, failure and entity retirement use local discard/clear without
running additional authored callbacks. This containment is distinct from full
native destruction/reconciliation. Self-unregister during its pending callback
remains a strict unsupported gate. Callback instance/entity retirement abandons
the current local history safely. Passive body VM storage gains no State fields;
live SceneWorld/host storage and restoration remain unsupported.
