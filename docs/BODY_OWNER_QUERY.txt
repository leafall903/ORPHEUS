Production behavior
-------------------
body_owner.Context requires an explicitly supplied lookup and watcher services.
The base World retains unknown-service behavior. Missing targets, absent components
and present null owners stay distinct. Callbacks recheck context/instance lifetime;
retired, replaced or malformed services poison strict execution.

The player's BodyWorld reads fresh Match identities: a live player body maps to
its player entity; player controller entities have no component43; known NPC bodies
have null player ownership. Unknown or retired body identities do not gain an
invented owner. The existing native-poll mechanism refreshes these live queries
every frame, so the Match adapter needs no additional dependency event hub.

Seven query tests cover guards/conversion/lifetime; six authored pilot tests
drive normal Match commands and prove projectile travel and14 damage against a
player and a training-NPC stand-in, misses/static cover/ally exclusion, a20-round
magazine, rejection during reload, reload completion, projectile range expiry,
incoming enemy-player command damage and death suppression.
The runtime's authored pistol ammo/reload graphs are exercised, not substituted.

Limits
------
The static tests do not create or possess D.Va's mech. Pilot critical-hit behavior,
all five actual PvE NPCs and full death/respawn/transform interaction remain open.
Component43 wire replication and original-client prediction have not been accepted;
this query is deliberately not added to the driver's trusted native-switch set.
