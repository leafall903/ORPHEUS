Implemented lifetime foundation:
- Bot.retain_corpse defaults to false. The future manual NPC creator must enable
  it explicitly. Existing training bots retain their normal respawn behavior.
- A retained dead bot is not scheduled for respawn. Even a stale explicit
  respawn callback cannot replace it. It stays in the entity/health catalog;
  normal dead filtering excludes it from enemy acquisition.
- Death event delivery remains unchanged. Ordinary updates still advance its
  death script through the existing bounded terminal animation window. This
  does not claim arbitrary long-running authored death effects or visual corpse
  persistence: those need original-client checks for the actual enemy bodies.
- Passive server state includes the policy, so it is not hidden causal state.

Manual NPC lifecycle API:
- npc.Definition requires full hero/body GUIDs, a name and explicit finite health,
  armour and shields. npc.spawn runs on the match thread, allocates a never-reused
  bot ID, opts into corpse retention, records its combat creation boundary, and
  queues body creates for spawned viewers. Later viewers use the normal catalog.
- npc.remove_spawned removes only manually created NPCs, including corpses.
  It stops body scripts, retires projectiles without explosions, removes pending
  attacks/respawns and combat state, and queues destroys. Existing map bots and
  player bodies are not selected by this operation.
- Five tests use the real Match combat and lifecycle with a training-body fixture.
  They do not establish the five Talon definitions' wire/component compatibility.
  The older extractor's pool labels differ from pools.py; retain raw variable IDs
  until actual NPC graph routing is checked. No NPC pool identity is guessed here.
