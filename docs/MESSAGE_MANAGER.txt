Native persistent message-State manager
Target: original PC build104319. Shared backend; State/mission integration open.

Persistent registration and selection
Receiving State9D6CF8AC asks managerD9AD40 to select a persistent sending
State38EE1100. This is a different mechanism from ordinary packet/Entry delivery.
The new message_manager backend restores the manager's explicit storage and
arbitration without installing engine identity, frame, filter or channel policies.
The sending State now mounts this manager through explicit SceneWorld Contexts;
the receiving State remains open. See MESSAGE_SENDER.txt.

D9A770 assigns a sequence for each native registration frame. A preserved
sequence advances the manager counter too, including subsequent registrations
of the same sender on another channel. A changed frame resets that counter.
Signed32 counter wrap is retained. Upsert matches the State's object identity,
copies the resolved record and preserves its position. Existing channel receivers
are dirtied in stored order; the callback is an explicit owner service, not an
inline execution of authored subgraphs.

D9B2B0 appends receiver identities, including duplicates. D9B440 removes a
sender by swapping the last row into its slot, then dirties remaining receivers.
D9B6C0 removes the first receiver occurrence using the same swap policy, without
notification. Empty channels are removed. An absent sender or absent channel is
harmless. Removing a missing receiver from an existing channel violates the native
precondition; Python refuses it instead of reproducing the out-of-bounds write.

Channel keys preserve exact uint32 entity, flags and message fields. The native
message field is the resource's low uint32, unlike the full GUID in Entry packets.
Selection searches the local entity then entity0 with identical flags/message.
Entity0 is not searched twice. Identities whose low29 bits are all ones do not
fall back to entity0. Channels sharing the native hash bucket remain distinct.

D9AD40 picks the highest float32 priority, including negative priorities. Equal
priorities prefer the resolved ordering flag. With the flag clear, the smaller
unsigned combined frame/sequence wins and a complete tie keeps the first row.
With the flag set, the larger combined key wins and a complete tie takes the
later row. The low sequence is sign-extended before OR, as in the original.
Unordered floating values enter the native equal-comparison branch; infinities,
NaNs and signed zero are retained rather than silently normalized.

Without a requested match count, only candidates that could replace the current
winner invoke the filter. With a count output, every candidate is filtered and
every accepted row contributes, including weaker and duplicate rows. D9AA50
collects all accepted senders in local-then-global storage order without ranking
or deduplication. Native filters temporarily expose sender/receiver scope data;
the manager receives an already resolved predicate. The full scope getter,
compiled filter engine and resource-to-priority lookup are not restored here.

Ownership and limits
Callers must supply explicit lifecycle validation, shared work-budget consumption
and dirty notifications. Validation surrounds callbacks and selection work.
Unknown filter policies/results are rejected. Selection passes copies of sender
metadata to predicates. Mutation during filtering/notification is unsupported;
terminal retire clears storage without filters or owner callbacks and may safely
interrupt a callback. An owner must retire its manager on teardown/failure.
Per-State terminal discard removes all its roles without callbacks and invalidates
a selection/notification interrupted by that discard. Other owners retain rows.

No automatic engine manager is created, and no native identity/mode/channel flags
or history frame are guessed. The strict sending State now registers and removes
its channels through explicit services, with native reply encoding. The receiving
State retains its previous unaccepted model. Complete receiver registrations,
queued dirtiness, parameter scopes, stacked/array output bindings, context outputs
and idle/receive subgraphs still need integration and separate evidence. Passive shared-manager export and
restoration are also outside this change.
