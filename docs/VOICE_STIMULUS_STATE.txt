Services and lifecycle
World.voice_context(entity) distinguishes unknown NotImplemented, known absent
host None and an explicit voice_stimulus.Context for the actual live component.
SceneWorld validates binding/identity and retires the context on unbind or fault;
a stale component fault cannot clear a replacement's context. Missing services
remain strict boundaries. Defaults do not install a manager or a mission driver.

Context supplies a separate global double clock in seconds and manager lookup.
Manager supplies descriptor loading, permission, submission, duration and part
queries. Stimulus contains GUID, playable and mode metadata. Submission returns
an explicitly obtained uint32 handle. Duration accepts(handle, GUID, mode), while
part accepts(State, part number). Unknown consumers cannot fabricate failed
resources, silent audio, zero duration or successful completion. None from load
means a known missing descriptor. Lookup results are sampled for each callback.
Owner/context validity is checked again after external callbacks.

Begin resets handle/attempts/duration, sets part1 and reads the global clock
before evaluating float32 delay/cooldown. It resets retry/submitted/failed and
registers the State even when a known manager lookup returns None. An absent
host returns before any cache reset or registration, matching the original.

The poll phase is separate
Native1B8C690 owns the +80 phase: it prepares instances, snapshots a VM registry,
dispatches +80 and1B74F60 auxiliary work, then performs later instance dispatch.
It is distinct from ordinary +70 ticking. Context.poll exposes only the shared
voice callbacks in an explicitly selected owner phase. It does not call the

Registry mutation during this partial poll is strict until native snapshot

Poll behavior
- Without a host or manager, return. Before submission, require elapsed >= delay.
  Resolve the stimulus through scalar config +20, require its descriptor playable
  byte78 and permission, then iterate targets. Native F64C20 conversion, uint32
  validity filtering and first-occurrence deduplication preserve target order.
  Empty targets still reach the explicitly supplied submission consumer.
- A valid handle marks submitted. A failed request marks failed and preserves
  any earlier failure. Failure queues ordinary FINISH only when elapsed is
  strictly greater than delay+cooldown. It does not synthesize the failure plug.
- With retry_at >0, wait for the global deadline. Query part+1 first. If the
  result is zero or NaN, query the current part; a positive second result waits,
  otherwise queue FINISH. A nonzero ordered first result increments the part
  byte modulo256, sets retry_at from a fresh clock read and queues timer2 now.
- Otherwise, a valid handle with a nonzero stimulus GUID queries duration.
  Missing descriptors still query with mode=false; a zero GUID returns without
  increasing attempts. Increment attempts modulo256; attempts >5 mark failed,
  even if that result is positive. Positive duration converts duration and
  cooldown independently to rounded native signed milliseconds. Overflow/NaN
  conversion yields INT_MIN. Sum as int64 and multiply in float32 by0.001 for
  the cached duration. Queue timer1 immediately, clear the handle and set the
  next deadline using the unquantized duration, cooldown and fresh double clock.

Timer1 writes cached duration to a supported dynamic output before following
the custom +160/m_onFinishedPlug. Timer2 follows that same custom plug without
a duration write. Other parameters do nothing. The native float setter ignores
absent/zero dynamic identifiers; other unresolved output kinds remain strict.
Explicit failure notification follows +168/m_F96FC964 without ending the State.
Generic State completion follows only m_onEndPlug for this strict VoiceStimulus:
the same-named custom voice plug must not run again at ordinary completion.
Ending, destruction or failure detaches the State from its context registry.
