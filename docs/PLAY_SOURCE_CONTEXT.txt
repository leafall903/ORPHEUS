PlayScript entity-instance source and request identity
Target: original Overwatch 1.74.0.0.104319; 2026-11-08.

The caller bound by a start entry differs from the new graph's instigator.
Entity-instance requests can now obtain their real component identity and cached
inherited source from a live SceneWorld binding. Submission and live transport
remain strict services; obtaining a valid context does not execute the request.

Production boundary
Instance.source_entity() implements the lazy source getter without a dependency
watcher. set_source_entity(uint32) performs the synchronous typed write and cache
commit. Component.play_loaded_graph adds optional instigator=uint32: new instances
seed it before defaults/overrides, with zero's owner fallback. None preserves the
previous core boundary, leaving allocation source unspecified. It does not infer
an instigator from the start-entry caller. Existing start bindings remain queued.

SceneWorld.play_script_context verifies the actual component and live instance
identity, obtains caller/owner from that component and reads the inherited source.
It verifies the lifecycle again after the effective-value read, which can invoke
State output callbacks. Detached, replaced or stopped sources cannot request a
context. This policy applies to declared entity script VMs, not abstract native
instance classes. Base World still requires an explicit context service.

VM storage observes cached_source_entity as a uint32 without reading the builtin,
running a getter or changing a valid cache. Unknown layouts and malformed cache
values remain errors. Stored body/server replay includes the field; shared-world
storage remains unsupported as recorded in SCENE_SCRIPT_HOST.txt.
