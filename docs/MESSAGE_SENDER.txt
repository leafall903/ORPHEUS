Native persistent sending message State
Target: original PC build104319. Explicit EntityInstance services; paired receiver open.

Runtime integration
Strict STU_38EE1100 now registers itself in the persistent message manager instead
of broadcasting an ordinary Entry packet. The State retains its authored params
for later receiver evaluation. Registration does not read or snapshot them.
Permissive legacy execution retains its previous transport model.

An explicit message_state.Host shares one manager across component Contexts.
Every operation uses the initiating component's budget and validates its current
world binding. SceneWorld accepts declared Contexts and retires them on detach,
replacement or failure. No global/TLS manager, native frame or role is inferred.
Owners provide priority-resource resolution, the native frame, policy inputs,
receiver dirty notifications and the separate once-only VM timer notification.
Unknown services, policies, results or target types remain strict.

D4C3E0 first removes every old key in its stored order. It evaluates the message
through scalar success plus first-Asset conversion and uses the low uint32 key;
zero skips priority, frame, role and target work. Priority is also a scalar Asset,
resolved by173BA30 to a resource containing float+8 and ordering-byte+C. A known
missing resource means0/false; an unknown lookup is not a missing resource.
The native frame getter runs even when an existing frame/sequence is retained.
Only a frame of-1 causes a fresh frame and unassigned sequence to be used.

The two target policy classes derive from plain STUInstance, not ConfigVar.
1D719351 uses its three authored bytes to select global channels.9B213168 collects
its nested targets through the generic config iterator with this State as watcher.
It preserves repeated valid entities, skips invalid/non-entity values and can
register both primary and secondary channels. Native instance flag3, State+C0,
mode and local/world identity results determine flags1/2/4/8/16/32. These inputs
are explicit Policy fields; their engine meanings are not guessed from names.
Only policy fields reached by the native branch must be known.

Normal State begin resets frame/sequence to-1, then the base begin path invokes
the registration update after class begin/enter hooks and before authored plugs.
Reentry, watched changes and ticking refresh registration while retaining the
assigned frame/sequence. The registered native tick list is distinct from an
ordinary packet delivery. Complete prediction, rollback and native frame phases
are not established by this integration with the existing VM scheduler.

The post-registration1B72510 call forwards to EntityInstance table262E740+E0,
which is the known null callback1CE5640. It does not evaluate transition plugs.
The Python backend leaves transition handling to the common State lifecycle.
An initial implementation mistook this for a transition check; final source
removes that extra call and has a regression for duplicated transition actions.
The final native probe executes the original forwarding helper and null callback.

D4DB20 initializes the notification flag from the authored secondary-channel
byte, global world-channel bytes or node policy enum. D4CDE0 accepts timer param1
only, sets the flag before calling VM+110 and does not call it twice. Ending
removes registrations and normal VM cleanup removes watchers/ticking. Destruction
and poisoned/detached owners discard their own manager rows without authored
callbacks. Other components sharing the manager retain their rows and services.
Cleanup after detachment cannot borrow a replacement context or poison its VM.
A terminal discard during a manager callback invalidates that operation.

Reply payload
D4D510 writes the low16 bits of sequence+204.185C120 emits a presence bit, then
variable-width unsigned16 only when the low word is nonzero. The old encoder
always omitted this reply. statescript.write_payload now preserves it. D4BAC0
reads the same value, zero-extends it and stamps its supplied native frame.
Cleanup retains the last sequence. Constructor-uninitialized native sequence data
is not claimed by the before-begin Python placeholder. Incoming manager history,
reconciliation and complete receiver payload behavior remain open.
