Controlled input and resource boundaries
----------------------------------------
Actual pilot commands on the normally selected mech enter 02CC/64's
0.5 s minimum tap window. Releasing after one frame still intercepts a
rifle shot. The first frame containing the deadline turns the box off
at roughly 75.2 resource and starts the authored 1 s cooldown. A new
press during cooldown can reactivate at expiry if still held. Releasing
that press during cooldown leaves the box off. Actual rifle inputs
distinguish the protected frames from the cooldown and released paths.

After depletion, uninterrupted held input leaves the box inactive as
resource reaches 10 and the 02CC/103 gate clears the low-resource
stack from variable 416. Release and a fresh press restart it. A real
Flashbang from behind interrupts both the active box and its 0.5 s wait
before the natural deadline. Forced closure reuses 02CC/97 to spend
the authored 1 s cooldown. The host maps impact to the command clock
when the controlled mech has missing command frames. Native world/input
phase order remains open. See ../dva-matrix-tap-resource-final.txt (6 passed)
and ../dva-matrix-authored-recharge.txt.

When forced control closes Matrix in a command gap of up to 32 frames
with its input held, the host settles the active 02CC/104 drain through
impact. The newly armed 02CC/53 recharge wait starts at that same
boundary and runs for the authored 750 ms. The bounded hold and
impact-to-command timing are host reconstructions. Actual Flashbang
tests compare continuous input with a 26-frame gap before and after the
tap minimum. The tests check resource at impact and after stun, the
recharge start, and that a delayed command cannot charge drain again.
See ../dva-matrix-resource-impact-final.txt (33 passed).

During a bounded held-input gap, the contact query samples the active
02CC/104 drain at the preceding command-phase boundary. This is a
read-only projection. An actual rifle round is intercepted with resource
left, and later rifle and Helix hits reach the mech after projected
exhaustion. The next mech command replays the gap and closes the authored
box at zero resource. See ../dva-matrix-gap-exhaustion-final.txt
(32 passed).

Contact also projects release while commands are missing. A known
release during a tap closes the box at the authored 500 ms minimum.
For a held button, contact uses the first neutral recovery frame
after the host's 32-frame hold window, subject to the tap minimum.
Actual rifle rounds verify both sides of each boundary. The next
neutral mech command replays the bounded gap and starts the authored
cooldown at the matching boundary with resource remaining. See
../dva-matrix-gap-release-final.txt (8 passed).

When a hard-control hit follows projected exhaustion or release
within retained pose recovery, the host settles the drain at the
natural close and preserves the cooldown and recharge anchor.
Exhaustion uses the projected zero crossing. For release, the host
samples drain at the preceding phase to match the graph's release
event before the next resource poll. Actual front Flashbang after
exhaustion, tap release or inferred release now matches continuous
commands for cooldown start, recharge start and resource at contact
and after stun. See ../dva-matrix-post-close-control-final.txt
(9 passed). The timings are reconstructed.
When a gap exceeds the 64-frame pose window but fits retained command
history, the mech VM carries the already active Matrix button through
the 32-frame hold and releases it on the following neutral frame.
The recovered frames stay unposed. A Flashbang after the projected
close can settle that close beyond the pose window. Continuous-input
comparisons verify recovery after 100 missing-frame intervals and
a Flashbang after more than 64 intervals. See
../dva-matrix-long-gap-final.txt (9 passed).

For a gap beyond retained command history, the host settles the
already projected Matrix close before the neutral replay. If the
authored recharge deadline falls in the skipped interval, the host
runs that Matrix instance at the deadline. Retained replay then
samples elapsed recharge normally. Continuous-command comparisons
verify 350-frame intervals for exhaustion, released tap, inferred
release and inferred release followed by actual Flashbang. See
../dva-matrix-beyond-history-final.txt (10 passed). This clock recovery
is reconstructed.

Implementation
--------------
tools.extract_projectile_tags exports an external version1/build104319 catalog
of all supplied003 definitions' STUTargetTagComponent arrays. It resolves
shared XML arrays, removes duplicates, ignores an explicit null GUID and
rejects other tag types. Game data and generated catalogs stay outside Git.
Runtime requires ORPHEUS_PROJECTILE_TAGS before imports. Unknown definitions
pass through Matrix; known WeaponVolley definitions lacking0145 are eligible.
This catalog is required input, not evidence that every eligible weapon's
runtime/ability has been restored.

Combat checks live enemy player mechs with active02CC/st3. It reconstructs the
attachment at the current combat eye and rotates boxes using current aim yaw
and pitch. Eye attachment and aim frame are NOT native-verified. Rays starting
inside a box intersect at0. Finite projectile sweeps compare the first Matrix
intersection with the first body/static collision. Earlier bodies/walls win.
Absorption removes the flight without direct/splash damage and retires its
confirmed owner/observer copies without the explosion-release record. Future
spawned fields are cancelled by removing their tracked shot. No resource cost
per absorbed shot is added; authored elapsed-time drain controls the state.

Hitscan pellets each perform their own box intersection. Hitscan target poses
still use existing history, but Matrix uses its CURRENT pose and active state.
Historical Matrix poses/activation timing, scheduler/input ordering and retail
lag compensation remain open. Melee and non-Volley beam consumers bypass this
path. Actual Mei 05E6/state 13 now verifies the 08BE frost exclusion. Spray
damages a controlled Matrix mech and the pilot at 5 m and misses at 12 m.
The authored target limit is 99. The host sweeps the rest of the current
flight after each body hit and remembers which bodies that packet has hit.
An aligned ally behind the mech takes one hit in the open, and an intervening
wall stops the same packet after the mech. The ray geometry is reconstructed.
See ../dva-mei-spray-piercing-regression.txt.

The 0B77 and 05E7 resource defaults start spray frost at 0.2, add 0.0285
per later hit and freeze on hit 30 for 1.3 s. The host keeps per-source
progress with a 1 s hit gap, takes the highest current source, caps the
slow at 70% and leaves an active freeze deadline unchanged by new hits.
Both forms lose weapon, forward and aim input while frozen. Matrix stops on
freeze. Ordinary thaw restores speed, aim and weapon input. Projected Barrier
cleanses the existing frost state and intercepts further packets.
Lethal rifle fire retires the frozen mech's status. The returned pilot and
the Call Mech replacement start without its frost. Source aggregation, aim
lock, input masking and the body-local clock are reconstructed. Native
status graph hosting, client ruleset routing and other cleanse cases remain open.
See ../dva-mei-frost-and-cleanse-regression.txt and
../dva-mei-frost-aim-lifecycle.txt.

The host reads the explicit 0B77/05E7 source settings slots 2FE6, 2FEA,
300D and 301F when populated. A 0.6 initial minimum, 2x accumulation
rate and 0.5x duration yield a freeze on hit nine for 650 ms. Two actual
sprays at a 0.55 minimum freeze after one hit each only with stacking
enabled. The source that reaches the combined threshold sets the
deadline. Bounds, aggregation and the source slot bridge are
reconstructed. The fixtures seed those slots and preserve the extracted
default fallback when they are absent.
See ../dva-mei-frost-settings-regression.txt.

Frozen D.Va retains full Self-Destruct or Call Mech charge. Fresh input
after thaw casts the corresponding ultimate. Detaching with partial
frost removes it from the bomb immediately, and the pilot has its own
new frost state if hit again. The detached fuse deals 1000 on its existing
deadline and refills Call Mech even while the pilot is frozen. Held
ultimate input during freeze cannot spend that refill.
See ../dva-frost-ultimate-final.txt and ../dva-frost-ultimate-regression.txt.

An actual spray with the initial frost setting seeded at 1 freezes the
controlled mech during Boosters or Micro Missiles. Boosters propulsion
stops and the authored 300 ms wait starts its 4 s cooldown. Missiles
aborted in windup spend no cooldown. Once the volley has launched,
freeze ends it and preserves its cooldown while in-flight rounds hit.
Fresh eligible input restarts each ability. See
../dva-frost-ability-interrupt-final.txt and
../dva-frost-ability-interrupt-regression.txt.

Actual Flashbang and spray freeze overlap in either order. Expiring

See ../dva-overlapping-frost-flashbang-regression.txt.
