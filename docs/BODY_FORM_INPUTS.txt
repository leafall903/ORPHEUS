External additive inputs
------------------------
ORPHEUS_GRAPH_SUPPLEMENT optionally names a gzip JSON file with version1 and only
graphs/entities sections. Its graphs use the ordinary extractor's record format;
entities uses full003 GUID keys and ordinary additional-entity definitions. The
loader preserves base modes, hero definitions and metadata. Conflicting graph or
entity records, duplicate graph indices and mode overrides are rejected.

ORPHEUS_MOVERS_SUPPLEMENT optionally names a JSON mapping of full body GUIDs to
the existing extract_game_movers.mover_of results. It can add missing body movers;
it cannot replace an accepted base record with different values. Both files are
read only. Keep them outside the source repository and the immutable runtime pack.
Set environment variables before importing the server modules.

The local D.Va lane generated a minimal7-graph/1-entity supplement from the existing
build104319 XML export and canonical base. Its mover supplement comes from0407's
existing003 XML via mover_of. No client/archive/full runtime copies are needed.
These are research inputs, not assets approved for Git publication.

BodyScript accepts explicit body_definition=GUID. Canonical hero entry remains
the default when that argument is omitted. Explicit forms resolve their own record
and0033 pools; missing or mismatched definitions fail instead of becoming a pilot.
Match validates alternate records/pools/movers before retiring the current body,
builds the new mover after selecting the new body, and initializes health and
statescript from that form. This does not implement a skill-triggered transition.
