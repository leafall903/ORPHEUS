Parent discovery and private reproduction
Parent main reported that Ability.can_start consumed an unready buffered press
then reinserted it with the current time. This refreshed a released press every
tick, so it could auto-start seconds later when cooldown completed. The isolated
lane had the same implementation. A real personal Zarya barrier reproduced both
the changing timestamp and an unwanted second Pet activation after release.

same configured window; raw resource inspection corrected that assumption.

Reviewed shared fix
Ability.take_press can retain the matching entry. can_start first checks a
retained entry and consumes it only after all cooldown/condition/stack gates
pass. Failed starts preserve the original timestamp rather than appending now.
The two method ASTs match the parent's reviewed uncommitted fix. No roll motion,
velocity backend or other parent changes are copied, and parent files are read
only. External ability-buffer-parent-provenance.json records both source hashes.
