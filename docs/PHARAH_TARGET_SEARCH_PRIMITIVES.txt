Radial geometry
C8E660 consumes a query centre, outer/inner radii and capsule feet/radius/height.
Without horizontal projection, its nearest capsule height clamps query Y to
feetY+min(radius,height/2)..feetY+max(height-radius,height/2). Horizontal mode

Mask and component97 stages -- subsequent checkpoint
The six STUConfigVarFilter fields at20/28/30/38/40/48 are respectively
m_84065FD1/m_1E14CCA8/m_4EA686DB/m_27CF71D5/m_66747E7D/m_89831602.
Their BCAAE0 roles are any/all/excluded tags, then any/all/excluded relationships.
This follows both the typed local schema and the original D0E10E..D0E14A
argument setup.312 in Assassin m_4EA686DB is an excluded-tag mask, not a
collection of unknown query flags. The six fields are uint64 masks.

mask_matches combines any-tag acceptance (or exactly3FFFFFFF), required tags
and excluded tags with the low three relationship bits. Given explicit native
query result Q and pointer identity S, relationship bit1 is !(Q && !S), bit2
is Q && !S, and bit4 is S. Any-relation can admit a candidate but cannot undo
missing required tags or excluded tags. All-relation masks intersect rather
than OR; high relation bits do not change these three tests. A known absent
reference skips relation gates. Unknown services must not be called absence.
Relationship is an explicit typed input; no team-equality approximation is used.

candidate_masks adds D0DA20's preceding gate. If the first mask is not exactly
3FFFFFFF, a nonzero aggregate of the six masks requires component97. Exactly
3FFFFFFF bypasses that presence test. If every mask is zero, D0DA20 skips
BCAAE0 entirely and passes this stage, although a direct BCAAE0 call with no
any-mask would reject. BCACB0 selects component25 (word0/bit25), whose58 holds
tags; component97 presence is a separate gate. No native tag producer is installed.
