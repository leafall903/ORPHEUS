The value interface matters
SetVar (1B6D300) invokes the value config's +28 method at1B6D381, then
performs its existing ordinary, indexed or keyed store. SetVars (1B6B560)
also uses +28, once for each pair whose target pointer is present. Using
the scalar +20 evaluator instead loses collected config-array values.

Both actions now use the existing play.evaluate_value interface. For06610EBC,
its +28 method1B779E0 collects all config-iterator values into a typed array.
Empty groups assign an empty array. Nested groups and nested array values
preserve iterator order; failed configs and scalar null yield no item, while
null members inside existing arrays are retained. A direct dynamic array
remains that array value rather than being flattened as a config group.
Unimplemented iterator classes and world services retain strict diagnostics.
This change does not add a generic iterator service or guess engine answers.

SetVar skips assignment and value evaluation when either the target or value
pointer is absent. SetVars differs: it skips a missing target, but a present
target with a missing/failed value receives typed integer0. Successful null
still overwrites the target with null. Pairs store immediately in authored
order, so later values can read earlier writes. A strict failure preserves
earlier stores and prevents later pairs and the action's output plug.
